# Chapter review checklist

## Before writing
- [ ] Read the target and adjacent chapters.
- [ ] Identify the exact reader question and prerequisite knowledge.
- [ ] Verify version-sensitive claims in current official docs / source.
- [ ] Record important claims in `evidence/NN.json`.

## Explanation
- [ ] Opening explains the topic in plain language, not only a title.
- [ ] Concrete scenario appears before dense terminology.
- [ ] Mechanism is explained in numbered steps.
- [ ] Equations define symbols, units, and assumptions.
- [ ] Tensor shapes / mapping indices are explicit where relevant.
- [ ] Paper results, official behavior, derived values, toy examples, and recommendations are clearly separated.
- [ ] Limitations and common misconceptions are included.

## Visuals and interaction
- [ ] At least one unique, topic-specific SVG.
- [ ] SVG has title, description, labels, and matching caption.
- [ ] Diagram is understandable with JavaScript disabled.
- [ ] Interactive control, if any, changes a meaningful state and is keyboard accessible.
- [ ] No repeated generic illustration.

## Engineering and QA
- [ ] One H1 and semantic main/article/section structure.
- [ ] Links work offline where intended.
- [ ] No required CDN, remote font, or runtime network request.
- [ ] Code blocks are labeled runnable / pseudocode / version-specific.
- [ ] No mobile page overflow at 360px and 390px.
- [ ] Course metadata, previous/next links, and generated manifest stay synchronized.
- [ ] Static and browser checks are reported honestly.
